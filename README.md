# Agile-Board-Lab
Agile Project Board, User Stories and Team Workflow - Lab 02

## Scenario
Library Book Search

## Team Roles

| Role | Responsibility | Owner |
|---|---|---|
| Coordinator | Maintains priorities, owners and board status | Ameed |
| Developer | Implements the assigned technical task | Ameed |
| Reviewer | Checks clarity, design and code changes | Ameed |
| Tester | Verifies acceptance criteria and records evidence | Ameed |

## Workflow
Backlog -> Ready -> In Progress -> Review -> Done

- Backlog: identified work
- Ready: story has an owner and acceptance criteria
- In Progress: work has started
- Review: code and criteria are checked
- Done: all criteria are satisfied and evidence is recorded

## User Stories
- US-01: Search books by title
- US-02: Search books by author
- US-03: Search books by subject
- US-04: View book availability
- US-05: Librarian adds a new book

## Definition of Done
- All acceptance criteria are satisfied
- Code is reviewed
- Tests are recorded
- README is updated


## Reflection
In this lab I learned how an Agile board helps a team plan work before writing code. Writing user stories with testable acceptance criteria made the requirements clear. Using the Backlog, Ready, In Progress, Review and Done columns showed the status of each task. Assigning one owner per task makes responsibility clear, and moving US-01 through the full workflow showed how team collaboration is tracked.
